# 连续完成音乐指令

日期：2026-11-03。状态：候选已更新本机；用户已确认真人指令连续执行并开始播放，但本次 Host 最终窗口核对失败，不宣称自动完成状态的全流程验收通过。

## 本批目标与边界

用户要求一句“桌面上的网易云然后搜索最近最热的一首歌播放”完成打开、选曲、搜索和播放，中间不因同一应用的普通界面更新而错误中断。原始请求、应用目标及全部步骤继续属于同一 Session Turn；“最热”使用本次读取的网易云热歌榜榜首，明确来源和更新时间，不固定歌名或依赖模型猜测。

已确认旧版本把尾部“播放”保留为关键词，未安排后续动作；网易云搜索结果原本只用于读回，不提供可执行媒体身份。现场出现窗口身份变化，组合回归另外复现同一窗口仅标题改变也中断搜索。现场是否还有前台切换等因素须继续实测，不把模拟标题变化当作唯一原因。

原生窗口只读检查另外发现：系统报告的主窗口一度是同进程的临时提示窗。启动器现在排除工具/不激活窗口，对已验证的网易云目标选择真正的播放器主窗口；一旦绑定仍禁止迁移到另一个窗口。

## 实现约定

- 只对已绑定应用的搜索，在每个操作边界重新校验原应用、注册目标、窗口、进程生命周期、路径、前台与控件，允许单纯标题变化。普通窗口授权和截图授权的严格合同保持。
- 增加显式 `NetEaseHotChart` 搜索语义并贯穿精确目标绑定。引号里的歌名、否定和不明确的附加动作不自动变成播放授权。
- 从网易云官方公开榜单读取当前曲目身份。网络只提供元数据，不能更改应用授权，不读取账号或凭据，不向模型发送窗口画面。
- 使用已绑定网易云程序及官方客户端播放协议提交明确曲目 ID，最多执行一次。请求后只核对本窗口的曲名、全部歌手和播放状态变化，再要求连续两个匹配样本；没有独立读回平台曲目 ID，不能声称完成了 ID 级回读。原先就匹配且仍播放的静止画面不证明本次成功，超时返回的匹配样本也不接受；试听明确报告为试听。
- 用户停止或替换输入继续取消原流程；不能为了连续执行而接受真正换窗、错误目标、未知控件或支付等额外动作。实际播放入口和状态验证不可用时如实报错，不重复播放或伪报成功。

## 验收

先记录解析与窗口连续性的失败回归，修复后检查身份、否定、引号、取消和单次执行边界。然后使用真实网易云核对动态选曲、精确搜索、同一曲目开始播放；最终从已安装元枢入口验证同一个请求完成全部步骤，另记真人语音结果。保留本机历史、设置及凭据，安装前备份，升级后核对；现场证据只放仓库外。

当前已完成公开榜单真实读取、播放器暂停状态的本机结构化读回和离线回归；这些不能替代实际播放。直接调用播放入口的工具测试被自动审批拒绝，原因仅为 `blocked by policy`，该命令没有执行，也没有通过改换工具重试。随后用户自行口述指令，并确认连续执行和实际开始播放；这与自动完成状态的核对分别记录。
