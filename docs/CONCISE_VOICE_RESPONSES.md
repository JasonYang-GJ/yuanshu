# 简短语音应答

更新日期：2026-11-02。状态：完整构建、隔离安装、本机升级、真实模型短答和本轮真人喊名短答均通过。

## 目标与问题

用户要求呼唤后简短应答，普通问题默认一句回答，明确要求时才详细展开。现场短呼唤进入了普通聊天，生成超过五百字的回答，完成约需六秒；重复停止短句也进入聊天。该时间包含当前模型响应，不能当成纯语音识别耗时。

Direct 接收模式此前只将休息指令分流，完整呼唤只在 Standby 下识别；普通聊天提示没有简答或仅回答当前问题的约束。当前安装版问题通过受控语音事件进入真实 WPF 处理器复现，旧代码报 `direct_call_was_sent_to_host`。受控事件没有使用真实麦克风或模型。

## 当前实现

- Direct 中现有有限完整呼唤词走本机 Call，直接回复“我在。”，不创建 Session/Turn、不提交模型。附带问题或动作的完整句保持原正常分流；可能属于呼唤的中间转写等完整句后再决定。
- 本地短答只保存临时呈现资格，绑定麦克风、输入版本、Host、Session 及当前 Turn 版本。新输入或状态变化清除；许可、活动任务与错误提示优先，不重新显示旧长文覆盖短答，也不写入聊天历史。
- “停停”等有限精确停止短句走既有取消入口，保持 Host 对取消和迟到结果的裁决，不提交一条停止聊天。附带其它内容的句子不按包含词误判。
- 新增供应商无关 `chat.general@3`，普通与所选记忆对话统一使用；默认一句、通常 60 个中文字以内，只答当前问题，禁止未经请求的自我介绍、心理分析或续写旧内容。明确要求详细解释、步骤、代码、创作或完整方案时按需回答，不截断输出。旧 v1/v2 文件保持。
- 记忆出站预览、确认复验和实际调用使用同一新版提示与哈希；旧版本/旧哈希确认不能继续发送。Provider、模型、工具权限、历史保存与 API 参数不变，不引入跨层流式播报。
- 短播报的回声判断仅过滤精确重复，避免“我在。”误吞下一句“我在学习……”；长播报保留原包含与相似判断。
- 播放时暂停视觉许可的识别资格，保留已撤销/已消费记录。正常未消费许可须重新可见准备并绑定新识别代次；旧音频和已消费的同一许可不能重新使用。
